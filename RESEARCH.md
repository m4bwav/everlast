# Research: everlast-protocol

Current understanding, open questions, the four-track search plan, and dated findings for the plugin as a whole (the skills carry their own). Changes it caused are in [CHANGELOG.md](CHANGELOG.md); lessons in [LEARNINGS.md](LEARNINGS.md); state in `evergreen.json`; test runs in [TESTS.md](TESTS.md); the working document is [README.md](README.md) and [protocol/PROTOCOL.md](protocol/PROTOCOL.md).

## Current understanding (2026-09-23)

- Always-on repository overviews do not raise agent success and cost tokens (three independent 2026 studies); short human-written rules are at best marginal; distilled setup procedures, solutions with dead ends, and decisions with reasons help when retrieved on demand. Everlast therefore keeps an eight-line always-on block and an index.
- Every vendor's memory converged in 2026 on a user-level plus private project-level store in markdown outside the repo (Claude auto-memory, Codex `~/.codex/memory`, Copilot Memory server-side, Gemini auto-memory with a review inbox; Cursor removed Memories). None survives a product switch. The portable layer is markdown in a repository the user owns; native memories get pointers. The frontier converged on the same substrate (files the agent edits, a background consolidation pass, versioned stores scoped per user or project: Anthropic memory stores and Dreams, OpenAI Dreaming, Letta Context Repositories), long-memory benchmarks are saturated, and independent tests put memory layers level with tuned RAG (R-20260923-1), so freshness is what separates designs now.
- Check before use is the best-supported practice of 2026: Copilot Memory cites code and re-validates it before use (merge rate 90% against 83%), agents check a memory's source about one time in five and act on superseded constraints about three times in four unless forced, and forcing the check adds 61 to 74 points (R-20260923-2). Everlast answers with `stale_after` (the Open Knowledge Format v0.2 name and rule), `recheck` and `verify` (C-20260923-3).
- Retrieval at this scale is lexical first: grep beat vector search when results came back inline, and semantic search pays as an addition to grep, not a replacement (R-20260923-3); `search` is BM25 over fields with aliases, and `bench/` scores it against an index scan (T-20260923-1).
- Cross-agent handoff designs converge on HANDOFF plus decisions plus tasks (ESAA event-sourced projection), with provenance anchored to files and commits outlasting prose.
- Keeping docs out of a shared repo: `.git/info/exclude` works but Claude Code rewrites it on some versions (issue #84954), so the lint re-checks `git check-ignore`; a global `core.excludesFile` would exclude `ai-docs/` everywhere and is rejected; `CLAUDE.local.md` or a home-dir import carries the pointer in that mode.
- Vendors redact only narrow token patterns; people and politics need the user's own rules and a redact list. Encryption at rest, when wanted: sops with age (per-file, diffable) or gocryptfs (folder); git-crypt is stagnant.
- Packaging: a repo can be its own Claude Code plugin and marketplace; `hooks/hooks.json` is picked up automatically; SessionEnd shares a 1.5 s budget (sync must detach); `CLAUDE_PLUGIN_DATA` survives updates. `~/.agents/skills` is read natively by Codex, Copilot, OpenCode and Windsurf; Cursor and Gemini need a link; `npx skills add` is the community installer with an open Claude-symlink bug. Cowork takes a zipped `.plugin`. `claude plugin eval` (2.1.269) grades with `file_exists`, `regex`, `tool_used` and a no-plugin baseline.
- Existing tools by real use: claude-mem (94.5k stars, transcript memory, own SQLite), compound-engineering (25.2k, git-tracked `docs/solutions/`), Karpathy's LLM wiki gist (48.7k stars, 9.9k forks; index, log and lint), MemPalace Cloud, agentmemory, Obsidian vaults; the closest designs on the same substrate are Letta Context Repositories and ByteRover (R-20260923-5). None does the two-tier privacy split or the excluded-folder mode; compound-engineering's solutions schema is adopted here.

## Open questions

- Does an on-demand index measurably beat auto-memory alone? No controlled study yet; watch cs.SE.
- Does Codex's plugin `hooks/hooks.json` share Claude Code's schema exactly? Untested; an adapter may be needed.
- Cross-product handoff quality has no benchmark; the plugin's own evals are the proxy. Retrieval and staleness now have one of our own (`bench/`, T-20260923-1), written by the same team, so it is a regression floor only.
- An external score, planned and not done in 0.4.0: an adapter that loads an Everlast doc set into LongMemEval-V2 (arXiv 2605.12493; its file-based memory controller setting fits a doc root directly) or a STALE-style probe (arXiv 2605.06527: plant a superseded or revoked entry, ask a question that needs the current one, score whether the agent notices), run with and without the check-before-use step. Revisit embeddings when paraphrase Recall@3 on that score, or on `bench/`, falls below 0.6, or when a real doc set's index has split more than twice (decision in `ai-docs/decisions/`).
- Does forcing `recheck` before acting on a stale entry move outcomes in practice, as 2608.25553 found in its setting? The `recheck` eval case is the first probe; it needs a sandboxed run (Linux or macOS) to execute. Ran under WSL2 on the evening of 2026-09-23 (T-20260923-4): the one run in which everlast-resume fired ran `recheck`, verified and passed; the two in which it did not fire edited without checking, so the probe is a trigger question before it is an outcome question.

### R-20260923-2 · 2026-09-23 · Check before use: forcing a check of a memory's source is the largest measured gain for agent memory in 2026
- track: subject, practice, testing · magnitude: 0.6 (a core practice was missing: entries carried a `verified` date but nothing forced a check) · applied: C-20260923-3 (stale_after, recheck, verify, index flag, principle 6), C-20260923-7 (SessionStart suffix), everlast-resume C-20260923-1
- GitHub Copilot Memory (public preview 2026-01-15, on by default for Pro and Pro+ since 2026-03-04) stores each memory with subject, fact, citations and reasoning; before use the agent re-reads the cited code on the current branch and discards or corrects a contradicted memory; unused memories are deleted after 28 days, the timer reset by a validated use. A/B: pull-request merge rate 90% with memory, 83% without; planted false memories were caught. Stale constraints (2608.25553, 2026-08-26): models checked a memory's source about one episode in five and still acted on a superseded constraint 74.7 to 77.3% of the time; forcing a check of the critical source added 61 to 74 points. STALE (2605.06527): the best system recognized only 55.2% of memories that were no longer valid. Re-checking stored memories by probing the environment with read-only tools lifted a pass rate from 39% to 73% (2609.11060). None of five memory systems tested enforces revocation by default (2609.08258). Everlast's analogue keeps the check read-only (`recheck`) and lets the agent re-run a proof only when it is safe, since re-running an arbitrary stored command is itself a risk.
- Sources: https://docs.github.com/en/copilot/concepts/agents/copilot-memory, https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/, https://github.blog/changelog/2026-03-04-copilot-memory-now-on-by-default-for-pro-and-pro-users-in-public-preview/, https://arxiv.org/abs/2608.25553, https://arxiv.org/abs/2605.06527, https://arxiv.org/abs/2609.11060, https://arxiv.org/abs/2609.08258

### R-20260923-3 · 2026-09-23 · Retrieval: lexical search holds up at this scale; semantic search is an addition, not a replacement
- track: tooling, testing · magnitude: 0.45 · applied: C-20260923-4 (search, aliases), ai-docs decision "Search is lexical first", C-20260923-8 (bench)
- A PwC study (2605.15184, 2026-05-14): grep beat vector search in 8 of 8 harness and model pairs when results came back inline (93.1 against 75.9 for Codex with GPT-5.4) and lost when results came back as files (55.2 against 67.2). Cursor (2025-11-06): adding semantic search on top of grep raised accuracy 12.5% on average (6.5 to 23.5), "the combination of these two leads to the best outcomes". Anthropic contextual retrieval (2024-09-19): hybrid BM25 plus embeddings cut failed retrievals 49%, 67% with a reranker; under about 200k tokens, put the whole corpus in the prompt. Coding agents default to files plus grep (Claude Code, Codex, Gemini CLI). For a doc set of tens to hundreds of entries that must stay stdlib-only and portable, BM25 over the entry fields with author-supplied aliases is the proportionate step; embeddings wait for evidence of paraphrase misses.
- Sources: https://arxiv.org/abs/2605.15184, https://cursor.com/blog/semsearch, https://www.anthropic.com/news/contextual-retrieval, https://x.com/bcherny/status/2017824286489383315

### R-20260923-4 · 2026-09-23 · Google's Open Knowledge Format v0.2 names the freshness fields; everlast adopts `stale_after`
- track: practice · magnitude: 0.3 · applied: C-20260923-3 (frontmatter `stale_after`), DOC-TYPES Check before use
- OKF v0.2 (2026-07-24; SPEC.md read 2026-09-23): `stale_after` is an absolute instant and "a concept is stale when `now >= stale_after`" (optional); `status` is `draft | stable | deprecated` (absent means stable); `verified` is a list of `{by, at}` events; `generated` is `{by, at}`; `sources` is a list of `{resource, ...}`. Knowledge Catalog serves OKF bundles since 2026-08-26. Everlast takes the `stale_after` name and rule and keeps its own `verified` (a date) and `status` values so existing entries and tools keep working; `never` is its own value for a timeless entry, which an OKF export would drop. An `export --okf` stays an option, not built.
- Sources: https://github.com/GoogleCloudPlatform/open-knowledge-format, https://raw.githubusercontent.com/GoogleCloudPlatform/open-knowledge-format/main/SPEC.md, https://cloud.google.com/blog/products/data-analytics/okf-v0-2-adds-trust-signals, https://cloud.google.com/blog/products/data-analytics/scale-okf-bundles-across-an-organization-with-knowledge-catalog

### R-20260923-7 · 2026-09-23 · Time and links: bi-temporal facts, newest version wins, typed relations
- track: subject · magnitude: 0.3 · applied: C-20260923-5 (typed Related labels and lint, per-fact stamps), C-20260923-4 (a superseded entry ranks below its successor)
- Zep/Graphiti keeps world time (`valid_at`, `invalid_at`) and system time (`created_at`, `expired_at`) on every edge and invalidates rather than deletes a contradicted fact. A fixed "newest version wins" rule reached 82 and 93% single-hop on MemoryAgentBench's conflict tasks against a prior best of 54 (2606.01435); capping memory size cut accuracy on updated facts from 92 to 77% (2606.27472). Everlast stays per entry (it is a curated doc set, not a fact store) and adds the two cheap parts: a typed `Related:` grammar shared with the Evergreen Protocol, so supersede and contradict edges can be checked, and an optional `(verified YYYY-MM-DD)` stamp on a single fact inside a multi-fact entry.
- Sources: https://github.com/getzep/graphiti, https://www.getzep.com/research/, https://arxiv.org/abs/2606.01435, https://arxiv.org/abs/2606.27472

### R-20260923-8 · 2026-09-23 · Consolidation: automate the reversible part, review the rest
- track: practice · magnitude: 0.35 · applied: C-20260923-6 (maintain, maintain --apply), C-20260923-7 (SessionStart count)
- Dreams never edits the live store (it writes a new one a person can review), and ACE (2510.04618) measured what an unreviewed rewrite does: one context collapsed from 18,282 to 122 tokens and accuracy fell from 66.7 to 57.1, below the 63.7 baseline. Background consolidation elsewhere works from the user's own sessions and replaces entries wholesale. Everlast therefore automates only what is deterministic and reversible (archive old done, abandoned and superseded entries, rewrite links, rebuild the index) and reports the judgment items (duplicates, contradictions, long-stale entries) every session instead of waiting for an agent to remember a prune pass.
- Sources: https://platform.claude.com/docs/en/managed-agents/dreams, https://arxiv.org/abs/2510.04618

### R-20260918-1 · 2026-09-18 · Indexes: on-demand maps help while always-on overviews do not; index lines need a purpose clause; back-links to the index are unneeded
- track: subject, testing · magnitude: 0.5 · applied: C-20260918-4 (PROTOCOL §8, DOC-TYPES summary field, `note --summary`, index line)
- "Code Isn't Memory" (2606.22417): a structural index exposed as on-demand tools took localization from 44.3 to 84.5 percent and cut tokens per solve, the complement of R-20260913-1's always-on result. Configuration smells (2606.15828, 100 repos): links without purpose or scope ("Blind References", 16 percent) are ignored or loaded whole; context bloat starts past 200 lines. Context rot (2605.12366): near-duplicate lines are the distractors that degrade recall, so index lines must differ. Karpathy's llm-wiki index is one line per page with a summary, read first, linted for orphans, no back-link rule. No published eval of a docs index; the proxy is paired with/without runs, median of five, first correct open within three tool calls. Back-links: the index-to-entry edge is what Obsidian shows and what the lint counts; nothing shows an agent using entry-to-index.
